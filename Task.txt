🛠️ MODÜL 1: JSON Compare (Algoritma ve Veri Karşılaştırma)
Amaç: İki JSON verisini karşılaştırarak eklenen, silinen ve değiştirilen alanları renkli ve okunabilir bir şekilde göstermek.

1.1. JSON Formatı ve Yapısı
JSON (JavaScript Object Notation); insanların kolayca okuyup yazabileceği, makinelerin ise kolayca ayrıştırıp (parse) oluşturabileceği hafif bir veri alışverişi formatıdır. Anahtar-değer (key-value) çiftleri ve diziler (array) şeklinde düzenlenir.

Örnek Basit JSON Yapısı:

JSON
{
  "name": "John Doe",
  "age": 30,
  "city": "New York",
  "roles": ["admin", "developer"]
}

1.2. İki JSON Dosyasını Karşılaştırma Yöntemleri
Görsel (Manuel) İnceleme: İki veriyi yan yana koyup bakmak. Sadece çok küçük verilerde işe yarar.

Komut Satırı Araçları: diff ve jq gibi araçlar terminal üzerinden satır kıyası ve filtreleme yapar.

Grafiksel / Web Araçları (JSON Diff vb.): Farkları görsel arayüzde renklerle sunar.

1.3. Teknik Detay: Metinsel Karşılaştırma vs. Yapısal (Structural) Analiz
JSON dosyalarını karşılaştırırken sadece metinsel (string/text) karşılaştırma yapmak yeterli değildir; nesne yapısının (object structure) ve anahtar-değer ilişkilerinin derinlemesine analiz edilmesi gerekir.

Metinsel Kıyasın Sınırı: Anahtarların (keys) sırası değiştiğinde metinsel araçlar içeriği aynı olsa bile tüm yapıyı "farklı" gibi gösterebilir.

Yapısal Analiz: JSON verilerini doğru kıyaslamak için nesnenin tüm alt özelliklerinde özyinelemeli (recursive) olarak dönen algoritmalar (örneğin JavaScript'teki lodash.isEqual) veya yapısal diff mantığı kullanılır.

1.4. DevMate JSON Compare ve AI Katmanı
Mevcut araçların temel işlevleri esas alınacak, ancak kullanıcı deneyimi ve bilgilendirme tarafında şu farklar yaratılacaktır:

Kullanıcı Dostu Arayüz: Değiştirilen, silinen veya eklenen veriler görsel olarak kod üzerinde kırmızı (üstü çizili), yeşil ve mavi vurgularla gösterilecektir.

AI Bilgilendirme ve Risk Katmanı: Standart karşılaştırma sonucunun üzerine yapay zeka katmanı eklenecektir:

"Şu alanda bir değişiklik yapıyorsunuz, dikkatli olun; verilerin silinmesine veya hata almanıza sebep olabilir."

"Buraya yeni bir ekleme yapıyorsunuz, bunu doğru yere ekleyeceğinizden emin misiniz?"

🔍 MODÜL 2: AI Log Analyzer & Stack Trace (Backend Log Anlaşılır Kılma ve İnceleme)
Amaç: Backend (Spring Boot / Java vb.) uygulama loglarını, bildirimleri, uyarıları ve hata izlerini (Stack Trace) karmaşık yapıdan arındırarak sade ve anlaşılır bir Türkçe metne dönüştürmek; yapay zeka desteğiyle durumu özetlemek.

2.1. Backend Log Analizinin Temel Kavramları ve Log Seviyeleri
Log dosyası; uygulamanıza istek gönderen sistemlere, uygulamanın arka plandaki çalışma durumuna, bildirimlere ve oluşan olaylara dair tüm kayıtların tutulduğu veridir. Sadece hataları kapsamaz.

Log Seviyeleri (INFO, WARN, ERROR, DEBUG):

INFO (Bilgilendirme): Sistemin normal çalışma akışına ve başarılı işlemlere dair bildirimlerdir ("User 102 successfully logged in", "Application started on port 8080").

WARN (Uyarı): Sistem çalışmaya devam eder ancak potansiyel bir riske veya sınıra dikkat çeker ("Connection pool utilization is high").

ERROR (Hata): Bir işlemin başarısız olduğunu ve müdahale gerektiğini gösterir ("Failed to process transaction").

DEBUG (Hata Ayıklama): Geliştirme aşamasında sistem adımlarını detaylı izlemek için basılan teknik ayrıntılardır.

2.2. Exception, Java Stack Trace ve Root Cause Analizi
Exception (İstisna): Kodun çalışması sırasında normal akışı bozan durumlardır.

Stack Trace (Çağrı Yığını İzi): Uygulamanın çalışması sırasındaki bir anı temsil eden çerçeve listesidir. İlk giren son çıkar (FILO) prensibiyle çalışır. Kodda bir hata veya özel durum oluştuğunda mevcut metoddan başlayarak programın ilk başladığı ana kadar olan çağrı sırasını listeler.

Root Cause (Kök Neden) ve Caused By: İç içe geçmiş karmaşık log akışlarında veya hata zincirlerinde durumun asıl kaynağını bulmak için Caused by satırları izlenir.

Örnek Java Stack Trace Kodu:

Java
public class StackTrace { 
    public static void main(String[] args) { a(); } 
    static void a() { b(); } 
    static void b() { c(); } 
    static void c() { d(); } 
    static void d() { Thread.dumpStack(); } 
}
Kod Çalıştığında Üretilen Yığın Çıktısı (Stack Trace):

Plaintext
java.lang.Exception: Stack trace
    at java.base/java.lang.Thread.dumpStack(Thread.java:1380)
    at StackTrace.d(StackTrace.java:13)
    at StackTrace.c(StackTrace.java:10)
    at StackTrace.b(StackTrace.java:7)
    at StackTrace.a(StackTrace.java:4)
    at StackTrace.main(StackTrace.java:2)


2.3. Sık Karşılaşılan Backend Log ve Hata Türleri
Yazılımcıların loglarda sıklıkla karşılaştığı ve anlamlandırmaya çalıştığı temel durumlar şunlardır:

NullPointerException (NPE): Henüz başlatılmamış (null) bir nesne referansı üzerinden işlem yapılmaya çalışıldığında oluşur.

SQLException: Veritabanı bağlantı, sorgu veya tablo/sütun eşleşme durumlarında ortaya çıkar.

Timeout (Connection / Read Timeout): Bağlanılmak istenen servisin veya veritabanının belirtilen sürede yanıt vermemesi durumudur.

Connection Refused: Uygulamanın erişmek istediği sunucunun (DB, Redis, Kafka vb.) kapalı olması veya bağlantıyı reddetmesidir.

2.4. DevMate AI Log Analyzer Rolü
DevMate AI Log Analyzer'ın temel amacı sadece hataları yakalamak değil, karmaşık ve okunması zor olan tüm log metinlerini geliştiricinin anlayacağı sade bir dile dönüştürmektir:

Log Ayrıştırma ve Görselleştirme: Karmaşık, binlerce satırlık ham log metnini (INFO, WARN, ERROR) kategorize eder ve temiz bir arayüzde sunar.

Metne Dönüştürme ve Özetleme: Log metnindeki teknik akışı, bildirimleri, uyarıları ve hata durumlarını sade ve anlaşılır bir Türkçe özet haline getirir ("Sistem başarıyla başlatılmış ancak veritabanı bağlantı havuzu %90 doluluğa ulaştığı için bir uyarı basılmış").

Kök Neden ve Çözüm Analizi: Eğer log içerisinde bir hata veya exception varsa, Caused by ve Stack Trace satırlarını inceleyerek kök nedeni (Root Cause) tespit eder ve çözüm önerisi sunar.

🔐 MODÜL 3: JWT Decoder (Kimlik Doğrulama & Token İnceleme)
Amaç: JWT içindeki bilgileri güvenli bir şekilde çözüp okunabilir hale getirmek, geçerlilik durumunu ve bütünlüğünü kontrol etmek.

3.1. Authentication ve JSON Web Token (JWT) Mantığı
Authentication (Kimlik Doğrulama): "Kullanıcı kim?" sorusunun yanıtıdır. Kullanıcının iddia ettiği kişi olduğunu doğrulayan süreçtir.

JSON Web Token (JWT - RFC 7519): Modern web uygulamalarında kimlik doğrulama sonrası verilerin güvenli taşınmasını sağlayan standarttır.

Dijital İmza Mantığı: Sunucu, JSON verisini kendi özel anahtarı (Private Key) ile imzalar; alıcı ise açık anahtar (Public Key) ile bu imzayı doğrular.

3.2. JWT Mimarisi ve Çalışma Mantığı
Çözümleme (Decoding) Süreci: Bir JWT Decoder, token'ın içine gömülmüş bilgileri ortaya çıkarır. Header ve Payload bölümlerini çözmek için gizli anahtar (secret key) gerekmez; bu kısımlar Base64Url ile kodlanmış JSON nesneleridir. İstemci tarafında çözümlenebilir.

Sistemdeki İletişim Akışı: Kullanıcı giriş yaptığında sunucu JWT oluşturur ve istemciye verir. İstemci bunu localStorage veya çerezde saklar. Sonraki isteklerde HTTP Authorization başlığıyla (Header) sunucuya gönderir. Sunucu token'ı çözümleyerek kimliği doğrular. Bu sayede her istekte veritabanı sorgusu atılma zorunluluğu ortadan kalkar.

3.3. JWT Bileşenleri
Örnek Çözülmemiş JWT Token:

Plaintext
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
Token noktalarla (.) ayrılmış üç bölümden oluşur:

Header (Başlık): Token meta bilgileri. Türü ("JWT") ve algoritması ("HS256", "RS256") yer alır.

Payload (Yük): Asıl verinin (claim'lerin) bulunduğu kısımdır.
Base64Url İle Çözüldüğünde Payload Çıktısı:

JSON
{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022
}
Signature (İmza): Header ve Payload bilgilerinin gizli anahtar ile şifrelenmesiyle oluşur. Token’ın iletim sırasında değiştirilmediğini doğrular.

3.4. Sektördeki Popüler JWT Araçları ve Kütüphaneler
JavaScript - jwt-decode: İstemci tarafında sadece çözümleme (decode) yapan hafif kütüphane.

Python - PyJWT: JWT oluşturma, çözümleme ve imzalama süreçlerini yöneten kütüphane.

Java - java-jwt: Auth0 tarafından geliştirilen gelişmiş Java kütüphanesi.

Online Araçlar - jwt.io: Geliştiricilerin token'ı yapıştırıp anında çözülmüş halini gördüğü popüler web aracı.

3.5. DevMate JWT Modülü ve AI Katmanı
Decoder Gösterimi: Token yapıştırıldığında Header, Payload ve Signature alanlarını renkli ve ayrıştırılmış biçimde gösterir.

AI Bilgilendirme ve Güvenlik Analizi: Token'ın geçerlilik süresini (exp) okur, "Token sürenizin dolmasına 5 dakika kalmış" veya "Token süreniz dolmuş" gibi anlık durum bilgisi verir. Algoritma türünü inceleyerek geliştiriciye bilgilendirme sunar.
